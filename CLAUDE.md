# ggege — образовательное приложение (ЕГЭ-подготовка для школьников)

Duolingo-style приложение: Next.js 14 (App Router) + Drizzle ORM (postgres-js)
+ Tailwind + Framer Motion + lottie-react + Zustand + react-latex-next/KaTeX.
Курсы: ЕГЭ Математика Профиль (courseId=11), ЕГЭ Физика (courseId=12),
ЛНИП Физика 7 (courseId=10) и другие.

## ⚠️ Критическое ограничение: изоляция от asfalt-app

"asfalt-app" под pm2-процессом `asfalt-app`. Это чужой проект, не имеющий
отношения к ggege. **Никогда не перезапускать, не останавливать и не

Перед любым `pm2 restart`/деплоем — снять `pm2 list` и запомнить
uptime/restart-count у `asfalt-app`, после деплоя — сверить, что они не
изменились. Перезапускать только сам `ggege` (и, если нужно,

## Деплой

```bash
git add <файлы> && git commit -m "..." && git push origin main
ssh root@168.222.192.167 "cd /var/www/ggege && git pull origin main && npm run build && pm2 restart ggege"
```

Если менялись только данные в БД (seed/update-скрипт), а не код приложения —
деплой (build+restart) **не требуется**: `DATABASE_URL` в `.env` указывает
на ту же продовую БД, что видит и прод-сервер, так что `npx tsx scripts/...`
локально уже пишет в прод.

Со статикой из `public/` (SVG-диаграммы и т.п.) тоньше: **изменение
содержимого уже существующего** файла подхватывается сразу после `git
pull`, без build/restart (Next.js standalone раздаёт его по тому же inode).
А вот **новый** файл, которого не было в прошлом билде — 404, пока не
сделать `npm run build` (копирует `public/` в `.next/standalone`) —
проверять `curl -s -o /dev/null -w '%{http_code}' http://localhost:3001/...`
до вывода "деплой не нужен".

## Наполнение курсов задачами (sdamgia.ru)

Курсы пополняются задачами, спарсенными с `phys-ege.sdamgia.ru` /
`math-ege.sdamgia.ru`. Основной паттерн — один seed-скрипт на юнит/урок,
см. `scripts/seedEGEPhysics-unit*-lesson*.ts` как образец (структура:
создать unit/lesson → на каждую задачу `insert challenges` → `insert
challengeOptions` с перемешанными вариантами). Пример скрапинга:
`scripts/scrape-sdamgia.ts`.

### Как достаётся условие задачи

Постранично: `test?theme=<ID>&sort=ids&page=N` (5 задач/страница,
`sort=ids` = по убыванию id = от новых к старым) — так собирается полный
список id темы. Дальше на каждую `problem?id=<ID>` вытаскивается:

- условие — `<div id="body...N" class="pbody">...</div></div><!--np-->`
- иллюстрация (если есть) — `<img src="/get_file?id=X">` внутри pbody
- готовые варианты ответа ("Тип 2", когда они у sdamgia реально есть) —
  спрятаны в HTML-комментарии рядом с текстом `generated from answers`.
  **Место разрыва этого маркера внутри комментария у sdamgia плавает**
  (`<!--auto ge...nerated from answers-->` в одной задаче,
  `<!--auto generated...from answers-->` в другой) — не завязывайтесь на
  точный текст маркера, ищите весь `<!--auto.*?-->` целиком и разбирайте
  варианты внутри по разделителю `N)&#8239;&#8239;...`
- решение (полезно для придумывания дистракторов, см. ниже) —
  `<div id="sol<ID>" class="solution">...`
- правильный ответ — скрытый `<div class="answer">Ответ: X</div>`
  (надёжнее, чем видимый "Ответ:" внутри текста решения)

### Конвертация формул в LaTeX

`<img class="tex" alt="...">` в тексте условия — alt это **словесное**
описание формулы для скринридеров ("дробь: числитель: X, знаменатель: Y
конец дроби" = X/Y, "в квадрате" = ², "корень из: начало аргумента: ...
конец аргумента" = √...), а не готовый LaTeX. Конвертируется вручную по
смыслу (или через Claude) в `$...$`.

**Важно про подстрочные индексы:** многобуквенный/кириллический подстрочный
индекс обязательно оборачивать в фигурные скобки — `$F_{тр}$`, `$E_{к}$`,
не `$F_тр$`/`$E_к$` (последнее в KaTeX/react-latex-next рендерится только
с ПЕРВОЙ буквой индекса как подстрочной, остальное — обычным текстом; была
найдена и исправлена задним числом в одном уроке, проверяйте на новых
задачах).

Символы-артефакты HTML: `&#8239;` (узкий неразрывный пробел) → обычный
пробел, `&#8288;` (word joiner) → убрать, мягкие переносы (`\xad` /
"мас­сой") → убрать.

### Таблицы данных в условии

Если в `pbody` встречается `<table>` — sdamgia просто рисует HTML-таблицу.
`question` в БД — это **plain text + `$...$` для KaTeX**, полноценный HTML
не поддерживается компонентом вопроса (`app/lesson/question-bubble.tsx`,
рендерит через `<Latex>{question}</Latex>`). Поэтому таблица переносится в
условие **не как текст**, а как аккуратная SVG-картинка (см.
`scripts/svg-tools/render_table.py` — пример на теме 217, задача про
F(x) пружины), подключённая через `imageSrc`, как обычная иллюстрация.

### Диаграммы/графики к задаче

**Никогда не рисовать диаграмму "на глаз" по тексту условия.** Всегда:
1. Скачать оригинал `curl -s "https://phys-ege.sdamgia.ru/get_file?id=<ID>"`
2. Разобрать геометрию: серый `stroke` (обычно `#ADAAAA`) — сетка, чёрный
   (`#010202`/`#000000`) — оси/стены/земля, цветной (обычно `#CC761F`) —
   сама кривая/вектор данных. Текстовые подписи чисел на осях у sdamgia
   зашиты как глиф-пути внутри `<defs>/<clipPath>` — не парсить их текст
   напрямую, читать визуально (см. ниже) или ориентироваться по
   `<rect>`-якорям внутри `<defs>`.
3. **Визуально свериться с оригиналом** — открыть его в Browser pane
   (см. `mcp__Claude_Browser__preview_start`/`navigate`, оригинал можно
   отдать локальным `python3 -m http.server` из папки со скачанным SVG,
   т.к. `file://` рендерится только статичным снэпшотом) и прочитать
   реальные числа-подписи осей глазами, не угадывать.
4. Перерисовать в своей палитре, используя `scripts/svg-tools/*` как базу
   (см. `scripts/svg-tools/README.md`), сохранить в `public/geometry/`
   с именем вида `phys<тема>_<id задачи>.svg`, подключить через `imageSrc`.
5. Снова визуально сверить получившийся файл с оригиналом бок-о-бок
   (скриншот) прежде чем класть в БД/деплоить.

Частый баг при такой перерисовке — подписи делений оси обрезаются, если
`viewBox`/`height` канваса впритык под сами линии сетки, без запаса под
текст под/слева от последней линии. Всегда оставляйте явный отступ
(`MARGIN_L`/`BOTTOM_PAD` в `render_energy_graph.py` — обход этого бага).

### Правильный ответ — всегда доверенный, никогда не перепроверять

**Правильный ответ = поле "Ответ:" со страницы sdamgia, копируется
буквально.** Никогда не пересчитывать физику/математику задачи заново,
чтобы "проверить" ответ sdamgia, и тем более не подгонять диаграмму под
свои вычисления вместо оригинала. Единственное законное применение
собственных физических рассуждений — придумывание **неверных** вариантов
(дистракторов), см. ниже.

### Дистракторы (неверные варианты ответа)

**Начиная с Unit 7 lesson 3 (theme 393) — 5 дистракторов на задачу, то
есть 6 вариантов ответа всего** (раньше в разных юнитах курса "ЕГЭ
Физика" было вперемешку то 4, то 5, то 6 — несогласованно; курс "ЕГЭ
Математика" всегда использовал 6). Явная инструкция пользователя: во всех
новых уроках — 6 вариантов. Карточка задачи (`app/lesson/challenge.tsx`)
рендерит любое число вариантов без ограничений (grid без `slice()`), так
что технических препятствий нет.

Когда у задачи есть официальные варианты sdamgia ("Тип 2", см. выше) —
берём их как есть (даже если их не 6 — это чужие проверенные варианты, не
подгонять их число под правило выше).

Когда официальных вариантов нет — **дистракторы должны быть
индивидуально подобраны под физику конкретной задачи**, не одной формулой
на все задачи подряд. Была системная проблема: 241 из ~300 старых задач
курса "ЕГЭ Физика" использовали фиксированную формулу
`[correct-1, correct+1, correct*0.5, correct*1.5, correct*2]` — из-за
этого верный ответ был статистически угадываем (единственное число с
соседями ±1) без решения задачи. Это исправлено (`scripts/
fixDistractorsEGEPhysics.ts`), но при добавлении новых задач без
официальных вариантов — придумывайте под каждую конкретно правдоподобную
ошибку школьника (забыл ÷2/×2 в формуле, забыл возвести в квадрат, ошибка
знака, не перевёл единицы, перепутал соседний участок графика/данные из
условия и т.п.), варьируя тип ошибки от задачи к задаче. Решение sdamgia
(`<div class="solution">`) — хороший источник правдоподобных "промежуточных"
неверных значений, но использовать его можно только для этого — не для
проверки самого правильного ответа (см. выше).

## Права выполнения команд

Проект держит расширенный allowlist в `.claude/settings.json` (git status,
git diff/log, `python3`/`node` — в т.ч. произвольный код, `npx tsc`,
`npx tsx scripts/*`, `npm run dev/build/start/lint`, grep/find/lsof/sed -n
и т.д.) — это осознанное решение пользователя, чтобы не спрашивать
подтверждение на каждый шаг типового скрипт-цикла разработки/сидинга.
Не сужайте это без явной просьбы. НЕ добавлены в allowlist: `npm run
db:push`/`db:studio`/`backfill:*` (миграции и массовые правки схемы/БД —
подтверждать каждый раз отдельно).

`.claude/settings.json` читается один раз при старте сессии — правки не
подхватываются на лету в уже открытом диалоге, только в новой сессии.
