## Общие правила кода и UI
- **Проверка:** `npx tsc --noEmit` + `npx eslint` на тронутых файлах. Dev-сервер на этой машине падает по памяти (конфиг `lingo-dev-bigmem` в `.claude/launch.json`); если tsc чист, а браузер кричит про сломанный модуль — `rm -rf .next/cache` и рестарт, не переписывать код.
- **Browser pane не компонует кадры** (`document.visibilityState` hidden): framer/rAF-анимации стоят, скриншот бывает устаревшим. Проверять по DOM/атрибутам, состояние форсировать `style.setProperty(...,'important')`, короткие скрипты, второй скриншот.
- **Эмодзи в интерфейсе не ставим** — иконки lucide или свои картинки (тексты Telegram можно).
- **Кнопки:** объёмная кнопка = плитка + тёмная нижняя грань; при нажатии грань исчезает, высота не меняется (`border-b-4 active:border-b-0`; для грани-тени `boxShadow` — `active:translate-y-[Npx]`). Общие правила в `app/globals.css`. Никогда не менять высоту/отступы на :active.
- **Анимации:** только `transform`/`opacity`. Не использовать `filter: blur`, анимацию `box-shadow`/`left`/`top`, `backdrop-blur` на мобильном, SVG-фильтры и `mix-blend-mode` на двигающихся слоях (лагает iPhone). `AnimatePresence mode="wait"` ненадёжен — использовать `key`-ремонт. Для framer `motion.g`: позиционирующий `transform` держать на статичной внешней `<g>`.
- **Не класть HTML в `<foreignObject>`** (Safari ставит не туда) — HTML-слой поверх SVG в процентах.
- **Hydration:** случайное и время — только после монтирования (`useEffect`) или детерминированно от пропа.
- **Lottie:** в `<Lottie>` из `@/components/lottie-player`, не из `lottie-react`; JSON из `public/` импортируется как URL (строка). Статические `lottie-react` без `dynamic ssr:false` ломают SSR.
- **Видео:** прозрачные webm (VP9) Safari не умеет — `components/alpha-video.tsx` (нужен HEVC `.mov`) или обычный mp4.
- **Звуки:** через `lib/sound.ts` (Web Audio), mp3/m4a, не WAV.
- **Стикеры:** без белой обводки, с мягкой запечённой тенью (кроме стикеров-мемов, которые просто стоят рядом с плашкой/текстом — `public/more-memes`, `public/lesson-pics`, `public/remember-stickers`: там оставляем оригинал с белой обводкой, вырезание даёт артефакты; оригиналы лежат в `docs/stickers/white-outline/`) (`docs/stickers/tools/soft_shadow.py`); персонажа-гуся Мигеля — `docs/miguel/`. Сундуки — только версии без тени (`public/chests/`).
- **Русские окончания:** `declensionRu`; не ставить тире рядом с числами (похоже на минус); «ЕГЭ» в озвучке — строчными «егэ».
- **Палитра ggege:** `GGEGE_PALETTE` (`src/constants/lessonButtonColors.ts`) — blue/raspberry/green/orange/purple/teal. Роли: фиолетовый — «ищем»/ключевой термин, зелёный — второй ключевой, оранжевый — «внимание», синий — угол/величина. Отдельные системы: верно/неверно (`CORRECT_COLOR`/`WRONG_COLOR`), голубой `#7dd3fc` в статичных SVG-диаграммах, фон `#161F23`.
- Стиль оформления пока только «Игровой» (`metal`); «Тёплый» (`cozy`) отключён.

## Наполнение задачами (sdamgia)
- Один seed-скрипт на урок (`scripts/seedEGE*.ts`): создать unit/lesson → `challenges` → `challengeOptions`. Верный ответ — поле «Ответ:» со страницы sdamgia **буквально, никогда не пересчитывать и не перепроверять**. Своё мышление — только для неверных вариантов.
- 6 вариантов на задачу (5 дистракторов); если у sdamgia есть официальные («Тип 2», комментарий `<!--auto…-->`, ищем `<!--auto[\s\S]*?-->` целиком) — берём как есть. Дистракторы подбирать под конкретную задачу (типичные ошибки школьника), не одной формулой.
- Формулы: `<img class="tex" alt>` — словесное описание, переводить в LaTeX `$…$` вручную. Многобуквенные индексы в фигурных скобках: `$F_{тр}$`. Артефакты `&#8239;`→пробел, `&#8288;`/мягкие переносы — убрать. Обязательно нормализовать `unicodedata.normalize('NFC')` (разложенная «й»).
- Таблицы условий — SVG-картинкой (`imageSrc`), не HTML. Диаграммы **никогда не рисовать на глаз**: скачать оригинал, разобрать геометрию по сырым координатам, визуально сверить, перерисовать (`scripts/svg-tools/`, в палитре), сверить бок-о-бок; каждую диаграмму сверять отдельно, не копировать форму с соседней. Для кривых проверять знак ключевого отношения между концами численно.
- Единицы/ответы в тренажёре с `$…$`: жанр ответа определяется по наличию `$`.

## Тренажёр (t-lesson)
- Иерархия: `t_courses` (предмет, класс) → `t_units` (тема; `block_title` — сворачиваемый блок) → `t_lessons` (урок/этап) → `t_challenges`. Привязка к курсу: `t_courses.courseId`; к заданиям ЕГЭ: `ege_task_links`.
- Типы M_ASC-задач рендерятся случайно (ASSIST/CONNECT/INSERT/SWIPE/SCROLL…) или фиксированно, если `type` задан прямо. Авторские неверные варианты хранятся с `correct=false`, верный — первым.
- В уроке должно быть ≥2 разных величины/задач, иначе пул дистракторов пуст («1 вариант ответа»).
- Конвенции по названию урока: «контрольн» → босс, «мифич» → мифический кейс, «босс-экзамен» → экзамен.
- Новый самодостаточный тип (*WALK) регистрируется: enum в БД (`ALTER TYPE "type" ADD VALUE`), `db/schema.ts` (`allTypesCT`, `t_challengesEnum`), `page.tsx` (case), `components/trainer-question.tsx` (case + исключение из общей нижней кнопки), `TQUIZ.tsx` (исключение из очереди «работы над ошибками», 2 места), `lib/trainerStageFlags.ts` (`STEP_BY_STEP_CHALLENGE_TYPES`). **Проще: урок на движке SCENEWALK** (см. ниже) — без нового типа.

# ПРИНЦИПЫ ПОСТРОЕНИЯ STEP-BY-STEP УРОКОВ (обязательны для каждого нового разбора и тренажёра)

Дети неусидчивы: много текста не читают и бросают приложение. Цель — чтобы захотелось открыть снова: позитивные эмоции, действие вместо чтения.

Движок — `components/geometry/scene-engine.tsx` (шаги `say`, `ack`, `fig`, `card`, `calc`, `remember`, `choice`, `build`, `system`, `pick`, `ege`, `custom`). Образцы: `lib/scene-lessons/probability.tsx`, `percent.tsx`, `derivative.tsx`. Движок сам перемешивает варианты (`shuffleOptions`, верный не на том же месте), у `SceneTrial` есть `allCorrect` (десерт), на 1-м и каждом 4-м верном в практике — `FieryMiguel`. Эталон переделки старого *WALK в SCENEWALK — `lib/scene-lessons/logSum.tsx` (исходники старых логарифмических разборов — тег `logs-lesson-original-2026-11-10`).

- Общие хелперы в `components/geometry/WalkthroughLog.tsx`: `SceneWrapper`, `useSceneFocus`, `useReplayNonces`, `BackButton`/`ReplayButton`, `TypedBig`, `TypedLineWithParts`, `RememberPlate`, `FieryFeedbackBanner`, `EllipsisPause`, `FormulaAssemble`, `MarkerLoop`, `glassStickerStyle`, `useWalkthroughCombo`. **Новый разбор сразу подключает их и админскую карту этапов** (`AdminSceneMap enabled` + `SCENE_MAP_LABELS` + `jumpTo`/`startStep`; `isAdmin` прокинуть из `trainer-question.tsx`).

## Правила содержания
1. **Маленькие порции:** одна мысль — одна строка до ~6–8 слов; длинное режем.
2. **Подтверждение тезисов:** после важной мысли кнопка `ack`, её подпись повторяет тезис («Понял, π = 180°»); кнопка `next` — тоже тезис сцены, не «Дальше».
3. **Без повторов:** не писать «Нажми…/Выбери…» над кнопками; вопрос над вариантами — 2–4 слова.
4. **Задача ЕГЭ — только карточкой** (`{t:'ege', …}`), решение шагами-вопросами; каждый вопрос подсвечивает свой кусок условия (`{{ключ|текст}}`, `focus`, по умолчанию текстовыделитель). Порядок: условие печатается → кнопка-цель → вопрос → пауза → подсветка → только потом варианты.
5. **Действие вместо объяснения:** ученик сам нажимает, двигает, собирает; мини-игры («нажми объект», «подпиши сам», «собери паззл/формулу кнопками», «выбери подходящий», переключатели с живым результатом). «Дальше» открывается после действия.
5a. **Варианты ответа всегда перемешиваем.** Верный не должен стоять первым (или на одном и том же месте) во всех заданиях: иначе ребёнок кликает наугад и ничему не учится. В данных верный ставим первым только для удобства автора, порядок на экране — случайный (`shuffle`), и верный не на том же месте, что в прошлом задании. Не подписываем «Кликни на вариант» и прочее очевидное под вариантами.
13a. **Шутка-вопрос «все эмоции в одном» (шаблон).** В каждом квизе — минимум один вопрос с юмором вида: «Ситуация (например, «x = 1 и x = −1 оба не подошли. Что делаем?»)» → варианты: правильное действие по теме («Считаем дискриминант») + эмоции («Плачем 😭») + «забить» («Закрываем тетрадь») + «позвонить кому-то» («Звоним маме»). Верный — один, остальные — детские реакции. Он ничему не учит, но даёт эмоции и запоминается. Таких вопросов — как можно больше, на каждую тему свои.
13b. **Десерт в конце каждого урока.** Последний вопрос квиза — «Кто теперь шарит в теме?» с 3–4 вариантами («Я», «Конечно, я», «Несомненно, я», «Кто же ещё, как не я»), **любой выбранный — верный** (`allCorrect`). Главная задача — подбодрить и внушить уверенность. Без слова «Бонус» и восклицательного знака. Варианты можно менять.
13c. **Подбадривание за верный ответ — Мигель, не Lottie-огоньки.** Огненные Lottie убраны из приложения; на 1-м и каждом 4-м верном ответе слева от фразы — случайный стикер Мигеля (`FieryMiguel`) + конфетти. Готовые промпты для Leonardo — `docs/miguel/leonardo-prompts-cheer.md`.
6. **Ответ в тренировке собирается из кнопок** (`FormulaAssemble`: слоты, клик «прилетает», обратный клик возвращает; в `product` порядок множителей не важен), а не выбор из 4 готовых.
7. **«Пробуй, пока не угадаешь»:** неверный вариант краснеет и блокируется, остальные активны, персистентное зумерское сообщение (`pickWrongTryPhrase`); верный завершает попытку. Ошибки мини-игр в зачёт урока не идут — только итоговая тренировка/квиз.
8. **Строго по очереди:** ничего не появляется одновременно — текст печатается → пауза → следующий элемент; следующий шаг ждёт конца печати. Картинку не перерисовывать, если можно сменить подсветку. Это касается и стикеров: сначала рисуется плашка/текст, и только через ~500 мс прилетает стикер (`RememberPlate` делает так сам). Сцена-запрет «ВНИМАНИЕ… нельзя» (эталон — `ForbidScene` в `type-logdefwalk.tsx`): плашка → стикер → вводная строка → пример → пауза → справа «прилетает» штамп «нельзя» → следующий пример; в конце пауза 1 с и кнопка-тезис («Понял, минусы нельзя»). Вопросы с ответом «да/нет» подписью «Выбери да или нет» не снабжаем (очевидно), фразу вопроса центрируем, «Сложность» (`DifficultyBadge`) ставим справа сверху. Никогда не запускать несколько анимаций одновременно.
8a. **Паузы на осмысление.** После каждого логического вывода («Если x₁ = 1» → пауза ≥800 мс → «то x₂ = c/a» → рамка → пауза ~1 с) даём ребёнку время дочитать и понять, и только потом идём дальше. Пара «левая/правая половина»: левую оставляем яркой ещё секунду после рамки, и только потом бледним её и пишем правую. Пауза нужна там, где вывод — новая мысль; для служебных переходов не растягиваем.
9a. **Последовательные вычисления — подсвечиваем текущее, будущее бледное.** Если на экране уже есть несколько шагов (x₁ = [ ] и x₂ = [ ]; левая и правая половина), то пока считаем первое, следующие стоят бледными (`opacity 0.3` + `grayscale`, как «на заметку»), а когда доходим до них — они становятся яркими (глаз ребёнка понимает «теперь смотреть сюда»). Пройденное (уже посчитанное) серым делать не надо, пока оно нужно для сравнения. Если левая часть бледнеет на время рассказа про правую, то после — снова яркая, чтобы увидеть всё вместе. Эталон — урок «Теорема Виета» (502).
9. **Смотрим только на новое:** после нажатия важной кнопки всё выше бледнеет (opacity 0,3); прошлые сцены — `SceneWrapper`, внутри сцены движок бледнит всё до последнего `ack`. В самописных сценах всё, что выше новой мысли (заголовочные строки, списки, кнопка — **целиком**, а не только крупный блок), оборачивать в один контейнер и бледнить после нажатия кнопки-подтверждения (`opacity 0.3` + `grayscale`). Новая сцена подводится к верху экрана (`useSceneFocus`). Сцена целиком влезает в экран телефона 375×812.
10. **Варианты ответа падают сверху** — класс `drop-in-options` на каждой сетке вариантов; новое задание серии тоже падает. Значения в пропуск «влетают» (spring), активный пустой пропуск — без пульса, переливается только «?».
11. **Изменилось от действия — видно глазами:** счётчики подпрыгивают (`Bump`), цель мини-игры крупно сверху («Бросков N из 100»).
12. **Формулу называем словами задачи** («Вероятность вишни — это» + дробь), дроби рисуем дробью, не «a / b».
13. **Весело:** шутки отдельными короткими строками по-зумерски, мемы и Мигель на ответах (`showAnswerMeme`, `reportGagaAnswer`), `FieryFeedbackBanner` на 1-м и каждом 4-м верном, мнемоники, шутки «За науку» по теме. Ошибка — без наказания (вспышка, тряска, смешная подсказка).
14. **Мини-игры подключают `useWalkthroughCombo`** (КОМБО-молнии 5/8 подряд с первой попытки).
15. Плашка «ЗАПОМНИ» — `RememberPlate` (золотая рамка, не красная: красный = ошибка), «ЗАКРЕП» — `ZakrepPlate`. Одна величина — один цвет во всём разборе.
16. Тригонометрическая окружность рисуется от точки справа **против часовой**. Диаграммы геометрии — через `GeoFig`/свои SVG на единой проекции.
17. Подсветка стороны фигуры: базовая линия остаётся, поверх тоньше/толще цветная дорисовывается `pathLength` 0→1; подпись — после дорисовки, bounce-спрингом; числа стартуют ×4–5 и отскакивают.
18. Кнопка «Непонятно» (вместо «назад») стоит во всех разборах автоматически через `BackButton`.
19. Квиз «Проверим себя» в конце + при желании бонус-вопрос с единственным вариантом.
